# v0.2.14 — ответ Эдуарду и smoke-проверка

v0.2.13 оказался визуальной перестановкой и не закрыл старые функциональные баги. Оба отчёта собраны в один проверяемый список; ниже состояние по фактически реализованному коду v0.2.14.

| Твой пункт | Где сейчас | Что будет в v0.2.14 |
|---|---|---|
| Категории тесные, список не скроллится | В v0.2.13 менеджер зажат внутри Settings, одна колонка и обрезанный overflow | Отдельный resizable-диалог до 1160 px, master-detail в две колонки на широком размере, адаптив в одну колонку на узком; дерево и детали имеют отдельные кастомные скроллбары |
| Непонятно, как работают правила | Технические названия и форма не складываются в понятное условие | Единая форма «Если [где искать] [условие] [что искать], отнести к [категории]», обычный поиск и regex подписаны человеческим языком, дополнительные флаги объяснены |
| Правило из «Нужно разобрать» улетает не в ту категорию | Категория могла неявно подставиться из списка | Категорию нужно выбрать явно; сохранение с `category_id=0` заблокировано и во frontend, и в backend |
| Дубли правил | Одинаковые правила могли накапливаться | Миграция схлопывает дубли внутри одной категории, unique index и frontend/backend-проверки не дают создать их снова; один паттерн в разных категориях по-прежнему разрешён |
| Непонятные иконки mini | Управление было неочевидным | В header используются единые SVG-кнопки; corner-lock, always-on-top, настройки, свернуть и скрыть имеют локализованные tooltip и `aria-label` |
| Corner-lock пропадает после рестарта | Сохранённый угол не был политикой запуска | Валидный сохранённый угол восстанавливает позицию от угла рабочей области и показывает mini при запуске даже после hide/tray-only |
| Dashboard закрывает mini | Открытие Dashboard скрывало виджет | Dashboard и mini могут быть открыты одновременно; `show_dashboard` больше не скрывает mini |
| Нет «свернуть» и «закрыть» | В header не было отдельных действий | `_` сворачивает окно, `×` скрывает его в трей; оба действия сохраняют трекинг, а показать mini можно снова из трея или Dashboard |
| Нет opacity | Прозрачность не настраивалась | Ползунок 60–100% с шагом 5 доступен в mini и Settings, значение сохраняется; применение через Win32 требует проверки на Windows |
| Stop занимает место в mini | Управление трекингом было в footer виджета | Stop убран из footer; остановка/возобновление остаётся в трее и в отдельном разделе «Отслеживание» Settings |
| `Tracked today` — главный hero | Крупнейшей цифрой было учтённое время | Hero теперь «Score за сегодня» + процент продуктивного; «Учтено сегодня» осталось вторичной строкой, а в expanded-режиме добавлены подписанные ранг и XP |
| Mini уходит под окна Windows | Флага always-on-top было недостаточно после системных lifecycle-событий | При показе, восстановлении и потере фокуса для закреплённого mini повторно вызывается `SetWindowPos(HWND_TOPMOST, SWP_NOMOVE | SWP_NOSIZE | SWP_NOACTIVATE)`; требуется проверка Win10/Win11 |
| Видео во время idle уходит в «Перерыв» | Chromium fallback терял часть сигналов воспроизведения | Свежий `tab.audible`, маркер в title вкладки или окна сохраняют статус `active`; stale-событие использует маркер окна. Muted-видео без media-маркера не вошло и остаётся в backlog |
| Не видно, какая версия установлена | Версия не показывалась в интерфейсе | Settings → About показывает runtime-версию пакета; конфиг сборки установлен на `0.2.14` |

## Smoke-сценарии перед отправкой

1. Открыть «Нужно разобрать» → «Добавить правило» → убедиться, что без выбора категории сохранить нельзя → выбрать категорию и сохранить.
2. Создать одинаковый паттерн в двух разных категориях → оба правила должны сохраниться; повторить его в той же категории → увидеть отказ как для дубля.
3. Открыть Categories & Rules → растянуть диалог до двух колонок → прокрутить отдельно дерево и детали → убедиться, что строки и кнопки не обрезаны.
4. В mini выбрать Large → проверить размеры 300×228, 340×252, 420×320 и 480×340; при слишком малом размере окно должно автоматически вырасти до безопасного минимума Large.
5. Выставить opacity 60%, 80%, 100% → на каждом значении скрыть и показать mini → перезапустить TTLI → последнее значение должно сохраниться.
6. Закрепить mini в каждом нужном углу → перезапустить Windows или TTLI → mini должен появиться у того же угла рабочей области.
7. При открытом mini нажать «Дашборд» → оба окна должны остаться видимыми.
8. Включить always-on-top → кликнуть Explorer, затем Chrome → mini должен остаться поверх обоих окон.
9. Запустить YouTube со звуком → не трогать ввод 2 минуты → статус mini должен остаться активным, не «Перерыв».
10. Нажать `_` → mini должен свернуться; показать снова, нажать `×` → mini должен скрыться в трей; в обоих случаях через минуту новые данные должны продолжить появляться.
11. Открыть Settings → About → убедиться, что показано `TTLI v0.2.14`.

## Что нельзя подтвердить Linux-проверкой

Win32 always-on-top, системное применение opacity, corner-lock после реальной перезагрузки, поведение Explorer/Chrome, tray lifecycle и media/idle fusion нужно прогнать на Windows 10/11. Muted YouTube без `tab.audible` и без маркера title сознательно не считается закрытым сценарием v0.2.14.
