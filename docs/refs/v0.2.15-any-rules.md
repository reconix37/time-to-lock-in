# v0.2.15 — Правила «Везде»: один список через | или , ловит всё (фидбек Эдуарда, раунд 3)

Источник: фидбек Эдуарда («категории не работают», «активитивоч работает ток так», «пили UX-фикс»). Реализовано Codex CLI по брифу /tmp/ttli-v0.2.15-any-rules-brief.md.

## Проблема
Пользователь хочет один паттерн-список (`tiktok|reddit|facebook|...`) на категорию, который ловит активность где угодно: в процессе, заголовке окна или домене — как ActivityWatch. Раньше: матч строго по одному полю (exe/title/domain), «черта» = ИЛИ только в regex-режиме, в legacy для title это AND всех слов, для exe — starts_with. Список через `|`/`,` молча не работал, приходилось плодить правила.

## Решение (v0.2.15)
1. Новый match_type **`any`** («Везде»): правило матчит, если паттерн найден хотя бы в одном поле (app | title | domain) — OR.
2. Разделители **`|` и `,`** оба работают как ИЛИ:
   - regex-режим: запятая вне фигурных скобок нормализуется в `|` (квантификаторы `{2,3}` не ломаются); хвостовой разделитель (`tiktok|reddit|`) — ошибка валидации.
   - legacy-режим: токенизация по `|`/`,`, contains по любому полю (OR). Один токен без разделителей — тоже contains по любому полю.
3. Авто-переключение legacy → regex в UI при вводе `|`, `,` или `\` (только для источника «Везде»).
4. Дефолт нового правила — источник «Везде».
5. Приоритет: `any` идёт последним при равном порядке (ранг 1, после domain/title/exe) — специфичное правило выигрывает у широкого.
6. Preview для «Везде» группирует по всей тройке (app|title|domain), а не по title.

## Поведение для пользователя
Одна категория «Socials» с правилом `Везде` + `tiktok, reddit, facebook, signal, whatsapp` (или через `|`) ловит: нативные приложения (по имени процесса), вкладки браузера (по заголовку/домену), плееры — без отдельных правил. История по-прежнему перекрашивается вручную (All rules → перекрасить).
